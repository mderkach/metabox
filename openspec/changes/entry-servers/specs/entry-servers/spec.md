## ADDED Requirements

### Requirement: AC-83 An inbound is created as an entry server

An inbound node of any server type in the schema (`mtproxy`, `shadowsocks`, `vless`, `trojan`, `hysteria2`, `socks`, …) SHALL be able to be created as an "entry server": a form with the port, the users or secrets (generated by the panel), the fake-TLS domain where the type has one, and the outbound the server's traffic leaves through, written as a `route.rules` entry by inbound tag. The port is checked against the dataplane, the panel and other inbounds.

#### Scenario: An entry server is created

- **WHEN** the user fills the entry server form for a server type of the schema
- **THEN** the config gets the inbound with secrets generated by the panel and a `route.rules` entry by its inbound tag for the chosen outbound

#### Scenario: A taken port is reported

- **WHEN** the user enters a port used by the dataplane, the panel or another inbound
- **THEN** the form reports the conflict

### Requirement: AC-84 An entry server has a client link and a QR code

An entry server SHALL have a client link (`tg://proxy?…`, `ss://`, `vless://` by type) and a QR code; the link is built for the LAN address or for the WAN address or a DDNS name the user enters, and the panel says when the WAN link cannot work (CGNAT, the toggle of AC-85 off).

#### Scenario: A link for the LAN address

- **GIVEN** an entry server
- **WHEN** the user opens its client link
- **THEN** the panel shows the link of the server type and its QR code for the LAN address

#### Scenario: A WAN link that cannot work

- **GIVEN** the router is behind CGNAT or the "reachable from the internet" toggle is off
- **WHEN** the user asks for a WAN link
- **THEN** the panel says the link cannot work

### Requirement: AC-85 A WAN port opens only by an explicit toggle

A WAN port SHALL be opened only by an explicit "reachable from the internet" toggle on the server: the daemon writes a `firewall` rule for that port, reloads fw4, removes the rule when the toggle or the server is turned off, and restores the previous rules when the write fails. Nothing else in the product opens a WAN port. On a platform without fw4 the toggle states that the port is open by default and offers to bind the server to the LAN address instead.

#### Scenario: The toggle opens the port

- **WHEN** the user turns on "reachable from the internet" on a server
- **THEN** the daemon writes a `firewall` rule for that port and reloads fw4

#### Scenario: Turning the toggle or the server off closes the port

- **GIVEN** a server with the toggle on
- **WHEN** the toggle or the server is turned off
- **THEN** the daemon removes the rule

#### Scenario: A failed write restores the rules

- **GIVEN** the `firewall` write fails
- **WHEN** the toggle is turned on
- **THEN** the previous rules are restored

#### Scenario: A platform without fw4

- **GIVEN** a platform without fw4
- **WHEN** the toggle is shown
- **THEN** it states that the port is open by default and offers to bind the server to the LAN address
