# Файлы, процессы, сервис

Всё, чем демон трогает устройство: запись конфига, вызовы `sing-box`, управление сервисом через procd, состояние транзакции Apply. Решения зафиксированы в [ADR-0002](../../../../docs/adr/ADR-0002-apply-protocol-and-config-ownership.md), здесь — как они выглядят в коде.

## Атомарная запись

Требование NFR-3 и AC-29: прерывание питания в момент записи не оставляет полузаписанный `config.json`. Последовательность ровно такая и сокращению не подлежит:

1. временный файл в **том же каталоге** — `rename` атомарен только внутри файловой системы;
2. запись данных;
3. `f.Sync()` — без него `rename` может дать файл нулевой длины после сбоя питания;
4. `f.Close()` с проверкой ошибки;
5. `os.Rename(tmp, dst)`;
6. `Sync()` на **каталоге** — иначе после сбоя каталог может не содержать новой записи.

```go
func writeAtomic(dir, name string, data []byte, perm os.FileMode) (err error) {
	tmp, err := os.CreateTemp(dir, ".metabox-*")
	if err != nil {
		return fmt.Errorf("временный файл в %s: %w", dir, err)
	}
	defer func() {
		if err != nil {
			os.Remove(tmp.Name())
		}
	}()

	if _, err = tmp.Write(data); err != nil {
		tmp.Close()
		return fmt.Errorf("запись %s: %w", tmp.Name(), err)
	}
	if err = tmp.Sync(); err != nil {
		tmp.Close()
		return fmt.Errorf("fsync %s: %w", tmp.Name(), err)
	}
	if err = tmp.Close(); err != nil {
		return fmt.Errorf("закрытие %s: %w", tmp.Name(), err)
	}
	if err = os.Chmod(tmp.Name(), perm); err != nil {
		return fmt.Errorf("права %s: %w", tmp.Name(), err)
	}
	if err = os.Rename(tmp.Name(), filepath.Join(dir, name)); err != nil {
		return fmt.Errorf("rename в %s: %w", name, err)
	}

	return syncDir(dir)
}
```

Имя временного файла не оканчивается на `.json`: сервис поднимается в режиме каталога (`sing-box -D /etc/sing-box -C /etc/sing-box run`) и сливает все `.json` каталога — временный файл иначе попадёт в конфиг между шагами.

`os.CreateTemp` создаёт файл с правами 0600. Права целевого файла берутся у существующего (`os.Stat` перед записью), а не назначаются константой: владелец мог их сузить осознанно. Служебные файлы демона — бэкап и состояние транзакции — лежат вне каталога конфига (это требование ADR-0002) и создаются с 0600: в них то же содержимое, что в конфиге, включая ключи.

Ошибка на любом шаге до `rename` обязана оставить `config.json` побайтово прежним. Это проверяется тестом, а не рассуждением.

В примере ошибка `tmp.Close()` на путях отказа не проверяется намеренно: запись уже провалилась, временный файл всё равно удаляется, а подмена причины отказа мешает разбирать инцидент. На успешном пути ошибка `Close` обязательна к проверке — там она означает неполную запись.

**Не проверено:** поведение `fsync` каталога на overlayfs OpenWrt. Риск и его статус — в ADR-0002 и [TechDebt](../../../../docs/TechDebt.md); пока замера нет, AC-29 не считается закрытым.

## Пути

Пути к каталогу конфига, бэкапу и состоянию приходят флагами. Значения по умолчанию — устройственные (`/etc/sing-box`, `/etc/metabox` по ADR-0002), но в коде они существуют только как значения флагов: тесты и стенд всегда передают свои, иначе прогон идёт по живой системе.

Если путь собирается из значения, пришедшего снаружи (имя версии конфига, имя rule-set), доступ идёт через `os.Root` (Go 1.24): он держит операции внутри каталога и не даёт выйти по симлинку или `..`. У `os.Root` нет `CreateTemp` — временное имя генерируется самостоятельно и открывается `root.OpenFile(name, os.O_CREATE|os.O_EXCL|os.O_WRONLY, 0600)`, дальше та же последовательность.

`filepath.Join` сам по себе от обхода не защищает: `Join("/etc/metabox", "../../tmp/x")` — валидный путь наружу.

## Вызов sing-box

```go
ctx, cancel := context.WithTimeout(ctx, 30*time.Second)
defer cancel()

cmd := exec.CommandContext(ctx, s.binary, "check", "-C", candidateDir)
cmd.WaitDelay = 5 * time.Second

var stdout, stderr bytes.Buffer
cmd.Stdout = &stdout
cmd.Stderr = &stderr

err := cmd.Run()
```

- аргументы — отдельными элементами, никогда не строкой для шелла: `sh -c` с подстановкой пути превращает имя файла в исполняемый код;
- путь к бинарю — абсолютный, из флага. `exec.LookPath` зависит от `PATH` процесса, а под procd он не тот, что в интерактивном шелле; имя, найденное через относительный элемент `PATH`, Go с 1.19 не отдаёт — возвращает ошибку с `exec.ErrDot`;
- `CommandContext` убивает процесс по отмене контекста, `WaitDelay` ограничивает ожидание процесса, который не вышел после сигнала или оставил открытыми трубы. Без `WaitDelay` зависший `sing-box` держит горутину бессрочно;
- `stdout` и `stderr` собираются раздельно и отдаются вызывающему дословно (ADR-0002). Вывод ограничивается по размеру: битый конфиг может дать мегабайты диагностики;
- код возврата — из `*exec.ExitError` через `errors.AsType`, а не разбором текста.

Проверяется каталог-кандидат (`check -C`), а не отдельный файл: сервис поднимется на слиянии всех `.json`, и валидировать нужно ровно то, что запустится.

## Сервис через procd

Управление только через init-скрипт — `/etc/init.d/sing-box restart`, `... running`, `... start` ([Constraints PRD](../../../../docs/PRD.md)). Прямой запуск бинаря, `kill` по pid и правка `/etc/rc.d` запрещены: procd владеет процессом, перезапускает его по `respawn` и не знает о чужом вмешательстве.

Рестарт при остановленном сервисе — штатный путь (AC-16), а не ошибка: демон обязан поднять сервис, а не сообщить, что рестартовать нечего.

Команды `check` у init-скрипта реального пакета нет — она есть только в стенде ([`init.d/sing-box:29`](../../../../.devcontainer/target/files/etc/init.d/sing-box), запись в [TechDebt](../../../../docs/TechDebt.md)). Демон валидирует конфиг вызовом бинаря напрямую и на эту команду не опирается.

Healthcheck после рестарта — опрос Clash API до успеха с ограничением по времени, адрес и секрет берутся из конфига-кандидата, wildcard-адрес приводится к loopback. Отсутствие секрета — штатный случай (форк отключает авторизацию при пустом `secret`).

## Состояние транзакции

Состояние пишется на диск **до** записи конфига — иначе питание, снятое между записью и стартом таймера, оставит устройство на новом конфиге без автоотката.

Срок хранится **длительностью** и признаком «применено, но не подтверждено», а не абсолютным временем: у роутера нет часов реального времени, после включения он стартует с эпохи и прыгает при синхронизации NTP.

При старте демон доигрывает незавершённую транзакцию: применение без завершения — откат к бэкапу; ожидание подтверждения с истёкшим сроком — немедленный откат; с неистёкшим — восстановление таймера. Все три ветки закрываются тестами.

Время в коде берётся не из `time.Now()` напрямую, а через зависимость, подменяемую в тестах, — иначе проверка окна подтверждения превращается в `sleep` на минуту. Как это тестируется — [Testing](./Testing.md).

## Внешние правки

Перед применением демон сверяет `sha256` файла с последним записанным им самим. Расхождение — отдельное состояние в ответе, а не молчаливая перезапись: конфиг мог поправить владелец по SSH.

## Ресурсы

Ориентиры NFR-4 — RSS ≤ 64 МБ и CPU в простое ≤ 1% ядра; на целевом BPI-R4 Pro с 8 ГБ RAM они достижимы с запасом и подлежат подтверждению замером. Смысл в другом: демон работает месяцами без перезапуска, поэтому лишнее удержание памяти становится утечкой. Отсюда:

- конфиг не держится в памяти между запросами, не копируется без нужды и не читается целиком там, где хватает `sha256`;
- прокси Clash API и поток соединений не буферизуются целиком;
- фоновых опросов по таймеру без потребителя нет: устройство большую часть времени простаивает.
