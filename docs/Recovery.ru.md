# Известные ограничения и как вернуть доступ

Что делать, если сеть за роутером с metabox перестала работать, и границы текущего релиза. Все команды ниже выполняются на роутере от root по SSH (Secure Shell); LuCI, стандартный веб-интерфейс OpenWrt, не нужен.

## Когда пропадает интернет

metabox запускает sing-box через свой сервис `metabox-singbox`. Когда перехват трафика LAN включён (`option enabled '1'` в секции `dataplane` файла `/etc/config/metabox`), сервис добавляет правила nftables в файрвол fw4, `ip rule` для UDP и фрагмент dnsmasq, который отправляет все DNS-запросы сети в sing-box.

Перехват работает по принципу fail-closed: правила остаются на месте, пока sing-box не работает. Если sing-box упал, не смог запуститься или перезапускается, соединения перехваченных устройств отклоняются, а DNS всей сети не отвечает, вместо того чтобы трафик шёл напрямую в обход прокси. procd, менеджер сервисов OpenWrt, сам перезапускает упавший sing-box. Правила снимает только явная остановка `metabox-singbox` или выключение перехвата.

Поэтому интернет пропадает, когда:

- конфиг sing-box сломан и sing-box не может запуститься;
- в конфиге нет DNS-входа на `dns_port` из секции `dataplane` (по умолчанию 5333): dnsmasq отправляет туда все запросы;
- нет бинарника sing-box или файла конфига: сервис не стартует, а правила от прошлого запуска остаются;
- недоступен удалённый сервер или узел, через который конфиг направляет трафик.

После установки перехват выключен. Устройства, которые не перехватываются (при `acl_mode 'listed'`, это значение по умолчанию, перехватываются только устройства, включённые на экране «Устройства» или перечисленные в секции `dataplane`), сохраняют своё соединение, но всё равно теряют DNS, пока sing-box не работает: DNS всей сети идёт через него.

## Что Apply откатывает сам

Apply в панели проверяет новый конфиг командой `sing-box check`, сохраняет предыдущий, перезапускает sing-box и выполняет проверку здоровья: отвечает Clash API (интерфейс управления sing-box), DNS-запрос через sing-box разрешается, правила перехвата на месте и процесс новый. Если проверка не прошла, предыдущий конфиг возвращается сразу.

После успешной проверки панель просит подтвердить изменение в окне подтверждения, по умолчанию 60 секунд (флаг `-confirm-window` у `metaboxd`). Без подтверждения демон восстанавливает предыдущий конфиг и перезапускает sing-box. Поэтому если после Apply браузер потерял связь с роутером, дождитесь конца окна: предыдущий конфиг вернётся.

Изменения настроек перехвата и списка устройств на экране «Устройства» проходят через то же окно и откатываются к предыдущим настройкам.

Транзакция хранится в `apply.json` в каталоге состояния демона (по умолчанию `/etc/metabox`) на постоянном хранилище. Если роутер перезагрузился или демон перезапустился во время Apply, демон доводит транзакцию при старте: незаконченный Apply откатывается, а открытое окно начинается заново целиком.

Автоматический откат не поможет, если конфиг был сломан ещё до Apply, если конфиг меняли вручную или если откату не к чему вернуться.

## Как вернуться без панели

Подключитесь к роутеру по SSH по его IP-адресу (`ssh root@<IP роутера>`). SSH не зависит от sing-box: он работает, пока работает LAN, даже без DNS и интернета.

По умолчанию конфиг sing-box — `/etc/sing-box/config.json`, а состояние демона лежит в `/etc/metabox`; секция `main` файла `/etc/config/metabox` может их перенести (`config_dir`, `config_name`, `state_dir`). Сначала прочитайте настоящие пути; команды ниже используют эти переменные, поэтому выполняйте их в той же SSH-сессии:

```sh
dir=$(uci -q get metabox.main.config_dir || echo /etc/sing-box)
config="$dir/$(uci -q get metabox.main.config_name || echo config.json)"
state=$(uci -q get metabox.main.state_dir || echo /etc/metabox)
```

### Посмотреть, что сломалось

```sh
logread -e metabox-singbox
logread -e sing-box
/etc/init.d/metabox-singbox status
```

`logread -e sing-box` показывает ошибку, с которой завершился sing-box, в строке с `FATAL`; `logread -e metabox-singbox` показывает ошибки перехвата и отсутствие конфига или бинарника sing-box. `status` выводит `running`, пока sing-box работает. Проверьте конфиг той же командой, что и демон:

```sh
sing-box check -c "$config" -D "$dir"
```

### Сразу снять перехват

```sh
/etc/init.d/metabox-singbox stop
```

Команда удаляет правила nftables, `ip rule` и таблицу маршрутов перехвата, фрагмент dnsmasq и перезапускает dnsmasq. Трафик LAN и DNS идут напрямую. Проверьте, что ничего не осталось; каждая команда должна ничего не вывести:

```sh
nft list ruleset 2>/dev/null | grep metabox_
uci -q get firewall.metabox_post
```

Остановленный сервис снова запустится при следующей перезагрузке. Чтобы он остался выключенным, выполните ещё `/etc/init.d/metabox-singbox disable`.

### Выключить перехват

Чтобы sing-box продолжал работать, но не перехватывал трафик LAN:

```sh
uci set metabox.dataplane.enabled='0'
uci commit metabox
/etc/init.d/metabox-singbox restart
```

При выключенном перехвате сервис снимает правила при старте.

### Вернуть прежний конфиг

Демон хранит в `$state/versions/` десять последних конфигов, которые заменил Apply, в файлах с шестизначным номером (`000001`, `000002`, …); наибольший номер — самый новый. Каждый файл — конфиг в том виде, в каком он был, байт в байт. Панель восстанавливает их из истории версий обычным Apply. Список версий по SSH:

```sh
ls -l "$state/versions/"
```

Соседний каталог `<номер>.rule-sets/` хранит весь набор файлов наборов правил этой версии, тех, на которые конфиг ссылается в `$dir/rule-sets/`; он может быть пустым. Версию без него сохранил демон старой версии, и она не меняет файлы наборов правил. Задайте в `v` номер версии, которую нужно вернуть; команды сохраняют текущие конфиг и файлы наборов правил в `/root`, ставят версию на место и перезапускают sing-box, только если проверка прошла:

```sh
v=000002
cp "$config" /root/config.json.broken
[ ! -d "$dir/rule-sets" ] || cp -R "$dir/rule-sets" /root/rule-sets.broken
cp "$state/versions/$v" "$config"
if [ -d "$state/versions/$v.rule-sets" ]; then
	mkdir -p "$dir/rule-sets"
	rm -f "$dir/rule-sets/"*.json
	cp -R "$state/versions/$v.rule-sets/." "$dir/rule-sets/"
fi
sing-box check -c "$config" -D "$dir" && /etc/init.d/metabox-singbox restart
```

Если `sing-box check` не прошёл, сервис не перезапускается; верните копии из `/root` на место. После ручной правки панель сообщает о внешнем изменении и отказывает в следующем Apply, пока не перечитает конфиг.

### Сбросить пароль панели

```sh
rm "$state/auth.json" && /etc/init.d/metaboxd restart
```

### Удалить metabox

У пакета нет скриптов удаления, поэтому сначала остановите сервисы:

```sh
/etc/init.d/metaboxd stop
/etc/init.d/metaboxd disable
/etc/init.d/metabox-singbox stop
/etc/init.d/metabox-singbox disable
apk del metaboxd
```

После этого трафик LAN идёт напрямую. apk оставляет `/etc/config/metabox`, если его меняли после установки, например настройками перехвата в панели, и удаляет в противном случае. Каталог состояния демона `$state` (история версий, пароль панели) и конфиг sing-box с каталогом `rule-sets/` остаются на роутере; удалите их вручную, если они не нужны. Пакет `sing-box-extended` тоже остаётся; удалите его командой `apk del sing-box-extended` после `apk del metaboxd`. Выполненная раньше, она оставляет пакет, пока от него зависит metaboxd, но убирает его из списка пакетов, установленных по запросу, и следующий `apk del metaboxd` удаляет оба. Скрипт установки также добавил ключ подписи `/etc/apk/keys/metabox-release.pem` и источник пакетов `/etc/apk/repositories.d/metabox.list`; удалите их, чтобы перестать пользоваться репозиторием metabox.

## Известные ограничения

- **Только OpenWrt 25.12 или SNAPSHOT.** В этих версиях пакетный менеджер apk. OpenWrt 24.10 и старше используют opkg и не поддерживаются.
- **Только aarch64.** Пакеты собираются для `aarch64_cortex-a53`, архитектуры прошивок mediatek/filogic. Роутеры на MIPS не поддерживаются.
- **Одно ядро.** Поддерживается только sing-box-extended, форк sing-box. Пакет оригинального `sing-box` не поддерживается, а собственный сервис форка `sing-box` должен оставаться выключенным.
- **Нет режима fail-open.** Пока sing-box не работает, у перехваченных устройств нет соединения, а у сети нет DNS (см. [выше](#когда-пропадает-интернет)). Каждый Apply к тому же оставляет сеть без DNS на несколько секунд, пока sing-box перезапускается.
- **Только IPv4.** Перехват, его список устройств и исключения работают с IPv4. Трафик IPv6 не перехватывается.
- **Один перехватчик.** Другой сервис, перехватывающий трафик LAN, нужно остановить до включения перехвата, иначе оба будут захватывать один и тот же трафик.
- **Только LAN, пароль необязателен.** Панель слушает только сети LAN. Без пароля любое устройство в LAN может менять маршрутизацию.
- **Проверенное железо.** Проект в стадии pre-release, проверен на Banana Pi BPI-R4 Pro.
