# ADR-0036. Хранить снимок файлов списков соседним каталогом рядом с версией конфига

- Статус: Proposed
- Дата: 2026-10-04
- Ответственные: владелец репозитория

## Контекст и постановка проблемы

[ADR-0033](./ADR-0033-keep-custom-rule-lists-in-the-singbox-config.md) разрешил держать большой свой список файлом в подкаталоге `rule-sets/` каталога конфига и потребовал, чтобы такой файл жил в одной транзакции с конфигом: «в истории версий файл хранится рядом с конфигом той же версии, откат возвращает оба». Транзакция Apply это уже делает — проверка кандидата, бэкап и автооткат покрывают и конфиг, и файлы `rule-sets/`. История версий ([ADR-0008](./ADR-0008-store-config-versions-as-numbered-copies.md)) — нет: версия хранит только байты конфига, восстановление уходит в Apply одним конфигом, а файлы списков остаются текущими. Конфиг версии, который ссылается на уже удалённый файл, отловит `sing-box check`, но конфиг, ссылающийся на изменённый файл, восстановится с чужим содержимым списка — маршрут разъедется молча. Риск записан в таблице ADR-0033 и в `docs/TechDebt.md`.

Решение нужно сейчас: панель начинает править большие списки файлом, и «откат на вчера» без списков перестаёт быть откатом.

Ограничения, заданные раньше:

- Раскладка ADR-0008: `<state-dir>/versions/` с правами `0700`, версия — файл `0600` с шестизначным номером без расширения, десять последних, номера не переиспользуются, повтор того же содержимого в историю не пишется. Демон прежней версии перечисляет каталог (`listIDs`, `listVersions` в `apps/metaboxd/internal/config/version.go`): подкаталоги и имена не по формату он пропускает.
- Отказ истории не останавливает применение (ADR-0008); восстановление — обычный Apply, отдельной записи в обход протокола нет.
- Файлы списков приходят в конверте применения, потолок которого — 16 МиБ (`maxApplyBytes` в `internal/httpapi/httpapi.go`). На overlay устройства свободны десятки мегабайт (ADR-0008).
- Файлы, которые демон пишет в `rule-sets/`, проходят проверку имени `validListName` в `internal/apply/apply.go`; чужое в подкаталоге демон не пишет и не удаляет.

В scope: где лежит снимок, когда версия считается сохранённой, что считается повтором, какие метаданные видит панель, как восстановление возвращает файлы, сколько это стоит места. Вне scope: сравнение списков между версиями в панели и сам протокол Apply.

## Критерии выбора

1. **Откат на старый демон** не ломает историю и не сбивает счётчик номеров: обновление аддитивное, без `BREAKING CHANGE`.
2. **Целостность версии при сбое питания**: версия без своего снимка или снимок без версии не выдаются за целую запись.
3. **Старые версии читаются**: история, сохранённая до решения, остаётся доступной и восстанавливается как раньше.
4. **Расход места** на устройстве с десятками свободных мегабайт.
5. **Стоимость реализации**: надстройка над существующей историей, без второго механизма.

## Рассмотренные варианты

1. **Оставить историю без списков.** Ноль работы, но риск ADR-0033 остаётся открытым: восстановление версии возвращает конфиг поверх чужих списков. С появлением правки больших списков в панели это прямая поломка отката. **Отклонён.**

2. **Каталог на версию: `versions/000007/config.json` и `versions/000007/rule-sets/`.** Так записано в `docs/TechDebt.md`. Версия — один объект, снимок неотделим от конфига. Но раскладка меняется несовместимо (критерий 1): демон прежней версии пропускает подкаталоги, поэтому после отката на него история выглядит пустой, а счётчик начинается с `000001` — и первый же `writeAtomic` упирается в каталог с тем же именем, сохранение версии отказывает на каждом применении. Старые версии-файлы пришлось бы либо мигрировать, либо поддерживать два формата чтения (критерии 3 и 5). **Отклонён.**

3. **Снимок в одном файле-архиве рядом с версией** (`000007.rule-sets.tar`). Совместим со старым демоном так же, как вариант 4. Но архивный формат — либо `archive/tar` с собственной обработкой путей при распаковке, либо самописный; одинаковые файлы соседних версий не разделяются, и каждая версия платит полным размером списков (критерий 4). **Отклонён.**

4. **Соседний каталог рядом с файлом версии: `versions/000007` и `versions/000007.rule-sets/`.** Файл версии остаётся прежним, рядом появляется каталог со снимком. Старый демон каталог пропускает, `000007.rule-sets` как номер не разбирается — история и счётчик у него те же (критерий 1). Старые версии — просто версии без соседа (критерий 3). Одинаковые файлы соседних снимков связываются жёсткой ссылкой (критерий 4). Недостаток: версия — два объекта файловой системы, и их согласованность обеспечивается порядком записи, а не атомарностью одного `rename`. **Принят.**

## Принятое решение

**Раскладка.** Рядом с файлом версии `<state-dir>/versions/NNNNNN` лежит каталог `NNNNNN.rule-sets/` — снимок верхнего уровня `rule-sets/` каталога конфига на момент сохранения версии: те же имена, те же байты, права `0600`, каталог `0700`. Снимок может быть пустым: «списков не было» — тоже состояние, к которому возвращается откат. Подкаталоги `rule-sets/` в снимок не входят: демон их не пишет.

**Что и когда снимается.** Снимок снимает `config.Store` в `SaveVersion` под тем же мьютексом, под которым читает каталог истории, — как `Backup` снимает бэкап списков. Сигнатура `SaveVersion` не меняется: цикл Apply по-прежнему зовёт её после бэкапа и до записи, поэтому снимок, как и конфиг версии, — состояние до транзакции.

**Точка фиксации — файл версии.** Порядок записи:

1. снять сироту `NNNNNN.rule-sets` следующего номера и черновик прошлой неудачной попытки;
2. собрать снимок в черновике, каждый файл — атомарной записью, затем `fsync` черновика;
3. `rename` черновика в `NNNNNN.rule-sets`, `fsync` каталога истории;
4. записать файл версии атомарно — с этого момента версия существует.

Обрыв до шага 4 оставляет сироту без номера: перечисление её не видит, следующее сохранение того же номера её снимает, подрезка истории — тоже. Версия без соседнего каталога, наоборот, означает «снимка нет», а не «списков не было».

**Повтор.** Версия не пишется, если совпадают и конфиг, и набор списков с самой свежей версией. Набор совпадает, когда совпадают имена и `sha256` каждого файла. Старая версия без снимка равна только пустому текущему набору: иначе после обновления демона первое применение с файлами списков не попало бы в историю. Изменённый только список даёт новую версию с тем же конфигом.

**Место.** Файл, `sha256` которого совпал с файлом под тем же именем в снимке самой свежей версии, не копируется, а связывается жёсткой ссылкой `os.Root.Link`. Ссылку файловая система может не дать — тогда файл копируется: экономия места не повод отказать в версии. Версии неизменяемы, и запись в общий inode не грозит: и снимки, и рабочие файлы пишутся только атомарной заменой, а не правкой на месте.

Худший случай — десять применений подряд, каждое с полностью новыми списками у потолка конверта: около 160 МиБ сверх рабочих файлов. Практический случай — списки меняются редко, и неизменённый файл стоит в каждом следующем снимке одну запись каталога. Удержание остаётся прежним: десять версий.

**Подрезка.** Вместе с лишними версиями удаляются их соседние каталоги, а также любой каталог `NNNNNN.rule-sets`, номера которого нет среди оставленных версий, — сироты оборванной записи и снимки, оставшиеся после подрезки демоном прежней версии.

**Метаданные.** `config.Version` получает `lists_sum` — отпечаток набора снимка, посчитанный потоковым `sha256` каждого файла без чтения снимка в память целиком; у версии без снимка поля нет. Ответ `GET /api/config/versions` получает `current_lists_sum` — отпечаток текущего набора в той же записи. Отпечаток набора — имена с суммами в стабильном порядке — считается одной функцией `config.ListsEtag`, той же, что даёт `etag` в `GET /api/config/rule-sets` и сверяет `lists_base` применения. Панель отмечает версию текущей, только когда совпадают и `sum`, и `lists_sum` (если он есть).

**Восстановление.** `POST /api/config/versions/{id}/restore` читает снимок и запускает обычный Apply конвертом: файлы снимка пишутся, текущие файлы, которых нет в снимке, удаляются. Имена, которые Apply не принимает (`validListName`), пропускаются — восстановление не трогает чужого в `rule-sets/` и не отказывает из-за него. Версия без снимка восстанавливается как раньше — одним конфигом, файлы списков не трогаются. Проверка рабочего каталога службы, `sing-box check` кандидата, бэкап и автооткат работают для конверта восстановления так же, как для правки из редактора.

### Область действия и границы

`apps/metaboxd/internal/config` (история, отпечаток набора), `internal/apply` (сборка конверта восстановления), `internal/httpapi` и `internal/contract` (ручки истории), панель — отметка текущей версии. Протокол Apply не меняется.

Решение уточняет ADR-0008 — раскладку, правило повтора и метаданные — и выполняет требование ADR-0033 об истории. Пункт проверки ADR-0033 «в `<state-dir>` не появляется файлов списков» относится к хранению списка вместо конфига; снимки истории — копии того, что лежит в каталоге конфига, а не второй источник правды.

## Последствия

### Положительные

- Восстановление версии возвращает конфиг и списки одной транзакцией: риск ADR-0033 «откат возвращает конфиг, но не файл списка» закрыт и для истории, а не только для автоотката.
- Обновление аддитивное: старые версии читаются, демон прежней версии видит ту же историю и тот же счётчик.
- Неизменённые списки почти не стоят места в истории.
- Панель отличает версию, совпадающую с устройством по конфигу, но не по спискам, и даёт её восстановить.

### Отрицательные

- Версия — два объекта файловой системы, согласованные порядком записи. Это больше кода, чем один файл, и больше состояний для тестов: сирота, версия без снимка, пустой снимок.
- Худший случай по месту — порядка 160 МиБ, что больше свободного overlay. Удержание по числу версий, а не по объёму, остаётся.
- `SaveVersion` читает текущие файлы списков в память целиком — как и `Backup`. При потолке конверта 16 МиБ это кратковременный пик на время применения.
- Восстановление версии со снимком требует совпадения рабочего каталога службы с каталогом конфига (проверка перед записью файлов), даже если файлы снимка равны текущим.

### Нейтральные или отложенные

- Сравнение списков между версиями в панели не делается: отпечатка достаточно, чтобы отличить версию.
- Удержание по объёму истории отложено до замера реальных списков на устройстве.
- Демон прежней версии подрезает только файлы версий; их соседние каталоги остаются до первого сохранения новым демоном.

## Совместимость, миграция и откат

Миграция не нужна. Версии, сохранённые до решения, остаются файлами без соседнего каталога: `lists_sum` у них нет, восстановление их списков не трогает, правило повтора считает их равными только пустому набору.

Откат на демон прежней версии: история и счётчик те же, соседние каталоги игнорируются, восстановление снова не трогает списков. Подрезка прежнего демона оставит каталоги удалённых версий — их снимет первое сохранение после возврата на новый демон, либо их можно удалить руками.

Контракт расширяется двумя необязательными полями (`lists_sum`, `current_lists_sum`): панель прежней версии их игнорирует, новая панель на демоне прежней версии видит их отсутствие и сравнивает только `sum`.

## Проверка решения

- `cd apps/metaboxd && go test ./internal/config/`: снимок переживает последующую запись списков; пустой набор даёт пустой каталог; версия без каталога отдаёт `ErrNoVersionLists`, а список и содержимое версии читаются; повтор считается по конфигу и набору; подрезка оставляет ровно десять соседних каталогов; сирота заменяется; права `0700`/`0600`; в каталоге конфига не появляется ни одного нового файла.
- `go test ./internal/apply/`: конверт восстановления пишет файлы снимка, удаляет лишние, пропускает недопустимые имена.
- `go test ./internal/httpapi/`: восстановление несёт файлы снимка; версия без снимка восстанавливается без конверта; отказ по рабочему каталогу отдаёт `409 workdir_mismatch`; список версий несёт `current_lists_sum`.
- `make schema-daemon`: в `apps/web/src/shared/api/daemon.generated.ts` появляются ровно два необязательных поля.
- На стенде: применить конфиг со списком, изменить список, восстановить первую версию — файл в `rule-sets/` возвращается побайтово, `ls <state-dir>/versions` показывает соседние каталоги.
