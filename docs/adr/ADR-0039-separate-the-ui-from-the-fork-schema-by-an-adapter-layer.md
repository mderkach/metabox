# ADR-0039. Отделять интерфейс от схемы форка адаптерным слоем и не терять нераспознанное в конфиге

- Статус: Accepted — решение принято 2026-08-30 в разделе A.2 [`../PRD.md`](../PRD.md) и перенесено сюда без изменения существа
- Дата: 2026-08-30
- Ответственные: владелец репозитория
- Заменяет: раздел A.2 [`../PRD.md`](../PRD.md)

## Контекст и постановка проблемы

Владелец назвал полное GUI-покрытие конфига приоритетом важнее скорости выхода (интервью `metabox-di-001`, Round 4). Схема форка большая и меняется с каждым релизом ([ADR-0038](./ADR-0038-target-the-sing-box-extended-fork-schema-only.md)): ручные формы под всю схему протухают на каждом релизе, а форма, написанная против чужого формата, ломается вместе с ним.

Вторая сторона — кто владеет конфигом. Конфиг на роутере может быть написан руками или другим инструментом, и панель обязана его открыть (Round 1: «конфиг может быть сгенерирован руками, UI должен его распарсить; нужны адаптеры и подсветка неверных правил»).

В scope: слои между схемой форка и экраном и правило обращения с чужим конфигом. Вне scope: способ получения схемы ([ADR-0001](./ADR-0001-generate-schema-from-fork-registries.md)), протокол применения ([ADR-0002](./ADR-0002-apply-protocol-and-config-ownership.md)), правила ручной правки JSON ([ADR-0043](./ADR-0043-treat-manual-json-as-a-feature-and-split-save-from-apply.md)).

## Критерии выбора

- Полное покрытие схемы интерфейсом (AC-5).
- Ломающее изменение схемы форка правится в одном месте и не доходит до экранов.
- Нормальный UX там, где он важен, а не только сгенерированная форма.
- Чужой конфиг открывается и не теряет того, чего модель не знает (AC-1…AC-3).

## Рассмотренные варианты

Варианты источника форм — из Round 5 интервью (вариант 1 — ручные формы, вариант 2 — генерация), варианты владения — из Round 1.

1. **Ручные формы под всю схему.** Лучший UX, но формы протухают на каждом релизе форка, и объём кратно превышает ядро продукта (риск R-3). **Отклонён.**
2. **Только формы, сгенерированные по схеме.** Покрытие по умолчанию, но без адаптера экран зависит от формы схемы, а в приоритетных сценариях UX хуже ручного. **Отклонён.**
3. **Генерация, ручные формы поверх неё и адаптерный слой между схемой и UI** — ответ Round 5: «фактически 1 + 2 + адаптеры». **Принят.**

Владение конфигом:

1. **Конфиг целиком принадлежит metabox** — панель генерирует его и не принимает чужого. Противоречит сценарию, где конфиг уже есть на роутере. **Отклонён.**
2. **Конфиг принадлежит пользователю, панель только показывает.** Снимает с панели генерацию и применение. **Отклонён.**
3. **Гибрид** — ответ Round 1. **Принят.**

## Принятое решение

Модель конфига — три слоя:

```text
┌─────────────────────────────────────────────────────────┐
│ UI Layer                                                 │
│  ручные формы (чеклист типов) + автогенерируемый         │
│  fallback-рендерер для непокрытых узлов схемы            │
└────────────────────────┬────────────────────────────────┘
                         │  внутренняя модель metabox
┌────────────────────────┴────────────────────────────────┐
│ Adapter Layer (версионированный)                         │
│  маппинг «схема форка ↔ модель metabox»                 │
│  при ломающем изменении API правится ТОЛЬКО этот слой   │
└────────────────────────┬────────────────────────────────┘
                         │  типы + валидаторы
┌────────────────────────┴────────────────────────────────┐
│ Schema Layer                                             │
│  генерируется из sing-box-extended, обновляется          │
│  механически при релизе форка                            │
└─────────────────────────────────────────────────────────┘
```

Адаптерный слой изолирует UI от изменений схемы, генерация даёт покрытие по умолчанию, ручные формы — нормальный UX там, где он важен.

**Владение конфигом — гибрид.** metabox владеет конфигом и генерирует его, но обязан разобрать произвольный `config.json`. Конструкции, которые модель не распознала, не теряются: они сохраняются и подсвечиваются в UI как нераспознанные или невалидные.

### Область действия и границы

Где слои лежат в коде:

- **Schema Layer** — генератор `tools/schemagen` и его артефакт `apps/web/src/shared/api/generated.ts` ([ADR-0001](./ADR-0001-generate-schema-from-fork-registries.md), строгие схемы — [ADR-0018](./ADR-0018-generate-strict-schemas-and-mark-what-the-panel-does-not-know.md)).
- **Adapter Layer** — не отдельный каталог, а сегменты `api` и `model` слайсов фронта, адаптация схемы конфига — в `entities/Config` и `entities/Rule` ([ADR-0005](./ADR-0005-keep-foreign-api-adapters-in-the-api-segment.md)).
- **UI Layer** — автоформы по схеме и ручные оверрайды поверх них ([ADR-0035](./ADR-0035-render-node-forms-from-the-generated-schema.md)).
- **Владение** — демон держит конфиг байтами ([ADR-0002](./ADR-0002-apply-protocol-and-config-ownership.md)), панель правит текст точечно ([ADR-0004](./ADR-0004-edit-config-text-in-place-on-the-client.md)), незнакомый узел помечается «UI не покрывает» (ADR-0018).

## Последствия

### Положительные

- Подъём версии форка механический: перегенерация схемы, правка адаптера там, где формат сломался.
- Чужой конфиг проходит round-trip без потерь (AC-1…AC-3 подтверждены корпусом).

### Отрицательные

- Три слоя вместо одного: каждое поле, которое показывает экран, проходит через схему и адаптер.
- Адаптер в коде не версионирован, как обещает схема слоёв: панель собирается на одной версии схемы. Расхождение версий ловится предупреждением ([ADR-0044](./ADR-0044-catch-schema-drift-in-ci-and-at-runtime.md)), а не вторым адаптером.

### Нейтральные или отложенные

- Полнота обратного разбора вручную введённого JSON в формы набирается итерациями (раздел 8 PRD).

## Совместимость, миграция и откат

Не применимо: решение действует с начала проекта и переносится из PRD без изменения существа.

## Проверка решения

- Golden round-trip по корпусу `apps/web/src/entities/Config/__tests__/corpus/` в `make test` (AC-1…AC-3).
- Тест-обход `ConfigNodeForm.coverage` открывает формой каждый тип inbound и outbound (AC-5).
- Линтер границ `apps/web/tools/fsdBoundaries.js` пускает сгенерированные схемы только в сегменты `api` и `model` сущностей: экраны читают модель, а не форму схемы.
