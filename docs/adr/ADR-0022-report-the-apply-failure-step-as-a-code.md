# ADR-0022. Сообщать шаг, на котором встал Apply, кодом, а не только текстом

- Статус: Proposed
- Дата: 2026-09-16
- Ответственные: владелец репозитория

## Контекст и постановка проблемы

Цикл применения сообщал о своём отказе одной строкой: `Transaction.Reason` заполнялся текстом ошибки, собранным обёртками по пути наверх — «запись конфига: временный файл в /etc/sing-box: no space left on device». Панель показывала эту строку как есть.

Отсюда два следствия. Первое: текст на языке демона доезжает до пользователя нетронутым, и в английском интерфейсе он остаётся русским — ровно то, что [ADR-0019](./ADR-0019-keep-interface-texts-in-the-slice-and-load-them-over-the-network.md) закрыл для отказов HTTP, отдав панели код. Второе: панель не может отличить «конфиг не записался» от «служба не перезапустилась» — для неё это одинаковые строки, и предложить разное она не сможет, даже когда захочет.

При этом сама строка нужна: в ней исходная ошибка шага, и по ней чинят. Выбрасывать её нельзя, как нельзя выбрасывать вывод `sing-box check` (ADR-0002).

В scope — как отказ цикла доезжает до панели. Вне scope — набор шагов протокола: он задан ADR-0002 и здесь не меняется.

## Критерии выбора

- Панель может показать причину на языке пользователя.
- Подробность шага не теряется: по ней чинят отказ.
- Код отказа привязан к шагу протокола, а не к тексту ошибки: сравнение ошибок по тексту запрещено правилами демона.
- Незнакомый код не оставляет пользователя без объяснения.
- Состояние на диске остаётся читаемым прежней версией демона: файл переживает перезагрузку устройства.

## Рассмотренные варианты

1. **Код шага рядом с текстом** — `Transaction` получает `ReasonCode`, шаги заворачивают свою ошибку типом `StepError`, панель берёт текст по коду и показывает исходную ошибку подробностью. Плюсы: причина переводится; текст сохраняется; код ставит тот, кто знает шаг. Минусы: у транзакции два поля об одном отказе, и их нужно держать согласованными. **Принят.**

2. **Разбирать текст на стороне панели** — искать в строке «запись конфига» и подобное. Минусы: текст — сообщение пользователю, а не контракт; правила демона это прямо запрещают, и любая правка формулировки ломала бы панель молча. **Отклонён.**

3. **Заменить текст кодом целиком** — оставить только `ReasonCode`. Плюсы: одно поле, никакой рассинхронизации. Минусы: исходная ошибка шага пропадает, а вместе с ней единственная подсказка, почему именно не записалось. **Отклонён.**

4. **Сохранить текущий подход** — только текст. Минусы: не выполняет цель — причина остаётся непереводимой. **Отклонён.**

## Принятое решение

Шаги цикла заворачивают свою ошибку в `apply.StepError` с кодом шага:

```go
return stepFailed(ReasonWriteFailed, fmt.Errorf("запись конфига: %w", err))
```

Набор кодов закрытый и объявлен в `internal/apply` рядом с транзакцией: `backup_failed`, `write_failed`, `restart_failed`, `healthcheck_failed`, `rollback_failed`. `Transaction` несёт оба поля: `ReasonCode` — шаг, `Reason` — исходная ошибка. Ошибка без кода оставляет `ReasonCode` пустым: это отказ, которого цикл не ждал, и врать шагом в таком случае нельзя.

Панель берёт текст по коду из словаря своего слайса, а исходную ошибку показывает под ним, как показывает вывод `sing-box check`. Таблица кодов типизирована набором из контракта ([ADR-0021](./ADR-0021-print-contract-enumerations-as-value-lists.md)), поэтому новый шаг у демона — ошибка компиляции панели.

### Область действия и границы

`apps/metaboxd/internal/apply` и слайс `features/Config/ConfigApply` в панели. Протокол Apply, его фазы и файл состояния в остальном не меняются.

## Последствия

### Положительные

- Причина отказа читается на языке пользователя, а подробность остаётся для того, кто чинит.
- Панель научилась различать шаги: `rollback_failed` — худший исход, и теперь его видно отдельно от «применение не прошло».
- Код ставит тот, кто знает шаг, а не тот, кто читает строку.

### Отрицательные

- У транзакции два поля об одном отказе. Разойтись они могут только через `release`, и это единственное место, где они заполняются вместе.
- Набор кодов повторяет шаги протокола: новый шаг придётся заводить в двух местах — в цикле и в словаре панели. Второе ловится компилятором.

### Нейтральные или отложенные

- Причина `unknown` в объяснении маршрута остаётся прозой: там одно значение, и решать его судьбу отдельно.

## Риски и меры снижения

| Риск                                                  | Вероятность и влияние                  | Митигация                                                                       |
| ----------------------------------------------------- | -------------------------------------- | ------------------------------------------------------------------------------- |
| Шаг заворачивает ошибку и теряет код при обёртке выше | средняя; причина без перевода          | `reasonOf` ищет код через `errors.AsType`, обёртка `%w` цепочку сохраняет       |
| Новый шаг добавлен в цикл, но не в словарь панели     | средняя; текст без перевода            | таблица типизирована набором из контракта — сборка панели падает                |
| Старое состояние на диске без `reason_code`           | высокая при обновлении; влияние низкое | поле необязательное: транзакция читается, код пустой, текст берётся из `Reason` |

## Совместимость, миграция и откат

`reason_code` — новое необязательное поле. Файл состояния, записанный прежней версией, читается как раньше; панель без поддержки поля его игнорирует. Обратный порядок — новый файл, старый демон — тоже безопасен: неизвестное поле разбор Go пропускает.

Откат — вернуть `release` строку: поле останется в контракте пустым.

## Проверка решения

- `cd apps/metaboxd && go test ./internal/apply/` — отказ записи даёт `write_failed`, отказ healthcheck — `healthcheck_failed`, и подробность шага не теряется;
- `make schema-daemon` — `REASON_CODE` в контракте панели;
- `pnpm --filter web build` — таблица текстов покрывает набор целиком, иначе сборка падает.
