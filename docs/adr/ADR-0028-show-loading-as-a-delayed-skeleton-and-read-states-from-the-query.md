# ADR-0028. Загрузку показывать скелетоном с задержкой, а состояния блока брать у запроса

- Статус: Accepted
- Дата: 2026-09-23
- Ответственные: владелец репозитория

## Контекст и постановка проблемы

Экраны панели решали одинаковые ситуации по-разному:

- **загрузка** — строка «Загружаю…» в шести местах, прочерк на обзоре, ничего на соединениях;
- **пусто** — прочерки, пунктирный бокс, пунктирная секция с формой, `Alert`;
- **отказ источника** — где `Alert`, а где ничего. `useConfigDocument` отдавал только `isPending`: при отказе конфига экраны правил, наборов и текста показывали пустое место и один тост, то есть ошибка проглатывалась.

Состояние выводилось по пустоте данных: при `isPending` набор правил уже был пуст, и экран наборов показывал форму «наборов нет» до ответа демона.

Разбор 2026-09-22 (`docs/TechDebt.md`, «Одинаковые ситуации решены разными идиомами») решил: загрузка — скелетоном, а не строкой; состояния — у TanStack Query (`isPending`, `isError`, `isFetching`); загрузка, пустота и отказ — три разных экрана; ошибки не проглатываются; скелетон не мигает на быстром ответе.

Факты о библиотеках, проверенные 2026-09-23:

- `Query.md` уже требовал тянуть данные экрана в загрузчике маршрута, но загрузчики тянули только словари.
- TanStack Router рекомендует загрузчик маршрута, который кладёт данные в кэш до рендера, «без вспышки загрузки». Экран загрузки маршрута появляется после `pendingMs` (по умолчанию 1000 мс) и держится не меньше `pendingMinMs` (500 мс).
- Навигация роутера идёт внутри перехода React: старый экран держится, пока новый грузится.
- Сам TanStack Query переходов React не поддерживает: прошлые данные удерживает React через `startTransition` вокруг `useSuspenseQuery`.
- В TanStack Query 5.103 устарели `prefetchQuery`, `fetchQuery` и `ensureQueryData`. Их заменяет `queryClient.query`.
- Практика для индикатора внутри экрана — показывать его с задержкой 200–400 мс, чтобы быстрый ответ не мигал.

Панель обязана открываться при лежащем sing-box (`Query.md`, «Отказы и недоступность»), и отказ одного источника не должен гасить экран целиком.

Вне scope: пустые подписи в карточках обзора (остались в TechDebt), вкладки конфигурации, счётчики и графики вне шести экранов.

## Критерии выбора

1. Состояние берётся у запроса, а не выводится по данным.
2. Быстрый ответ не показывает скелетон вовсе; медленный показывает, а не замерший экран.
3. Отказ источника виден на месте блока с причиной и повтором; экран при этом открыт.
4. Ошибка, которую экран не обработал, видна, а не превращается в пустой экран.
5. Без устаревших API библиотек.
6. Без новых зависимостей; примитивы shadcn, а не своя разметка.

## Рассмотренные варианты

1. **Загрузчик маршрута плюс флаги `useQuery` внутри экрана.**
   - Загрузчик ждёт данные экрана через `queryClient.query(options).catch(...)`. Быстрый ответ показывает экран сразу с данными, медленный — общий скелетон экрана после `defaultPendingMs`.
   - Внутри экрана `isPending` показывает скелетон с задержкой появления, `isLoadingError` — блок отказа, успешный пустой ответ — `Empty`.
   - Непредвиденная ошибка уходит в `defaultErrorComponent`.
   - Отвечает всем критериям.
   - Минус: два механизма загрузки — роутера и блока — нужно держать согласованными.
   - **Принят.**
2. **Только флаги `useQuery` и задержка скелетона, без загрузчиков.** Проще, но каждый переход между экранами проходит через скелетон на первом кадре, а расхождение с `Query.md` о загрузчиках остаётся. **Отклонён.**
3. **`useSuspenseQuery` с `Suspense` и `errorComponent` маршрута для всех ошибок.**
   - Отказ любого источника гасит экран целиком: при лежащем sing-box экран прокси не откроется, а обязан (критерий 3).
   - Флагов `isPending` и `isError` у `useSuspenseQuery` нет, а решение 2026-09-22 требует брать их у запроса.
   - **Отклонён.**
4. **Оставить строку «Загружаю…».** Противоречит решению 2026-09-22 и не отличает загрузку от пустоты. **Отклонён.**

## Принятое решение

**Загрузчики маршрутов** (`apps/web/src/app/router/Router.tsx`):

- ждут данные экрана: конфиг для раздела конфигурации, прокси и подписки для экрана прокси, прокси и историю трафика для обзора;
- берут их через `QueryClientInstance.query(options).catch(keepFailureForScreen)`, отказ не бросают: он остаётся в кэше, и его показывает блок экрана;
- `prefetchQuery`, `fetchQuery` и `ensureQueryData` не используются.

**Роутер:**

- `defaultPendingMs: 300` и `defaultPendingComponent: PendingPage` — общий скелетон экрана;
- `defaultErrorComponent: ErrorPage` — граница стоит у каждого маршрута внутри оболочки, поэтому сайдбар остаётся.
- `ErrorPage` говорит словами пользователя: что-то пошло не так, конфиг и sing-box на роутере не затронуты. Действие — обновить страницу, текст исключения лежит под раскрытием для отчёта.

**Блок экрана:**

- **загрузка** — `isPending` показывает `SkeletonRows` или `Skeleton` с классом `PENDING_REVEAL`: проявление с задержкой 200 мс через `tw-animate-css`;
- **отказ** — `isLoadingError` показывает `QueryFailure` с причиной через `failureText` и «Повторить» по `refetch`. Отказ поверх данных (`isRefetchError`) их не прячет, о нём говорит тост из `meta`;
- **пусто** — успешный ответ без данных показывает `Empty`. «Пусто из-за отбора» — отдельный `Empty` с кнопкой сброса;
- `useConfigDocument` отдаёт запрос файла (`query`), и экраны раздела конфигурации берут состояния у него.

**Тексты.** Ключи отказов чтения живут в `shared` под `source.*` и общие для тоста в `meta` и для блока `QueryFailure`. Ключи отказов действий остаются под `toast.*`.

**Примитивы.** `skeleton` и `empty` добавлены через `shadcn add` в `shared/ui/shadcn`, `SkeletonRows` и `QueryFailure` — свой код `shared/ui`.

**Потоковые экраны** (обзор, соединения) идут мимо Query. Там загрузкой считается «первый снимок потока не пришёл»: `sampledAt === null` у своего стора, а `null` вместо значения плитки означает скелетон. Прочерк остаётся только за величиной, которой нет вовсе.

### Область действия и границы

- `apps/web/src/app/router/`, `apps/web/src/app/ui/PendingPage.tsx`, `ErrorPage.tsx`;
- `apps/web/src/shared/ui/SkeletonRows.tsx`, `QueryFailure.tsx`, `styles.ts` (`PENDING_REVEAL`);
- `apps/web/src/entities/Config/model/Config.document.ts`, ключи `meta` в `entities/*/api`;
- экраны правил, наборов, текста конфига, прокси, соединений и обзора, панель объяснения маршрута, диалог истории версий.

## Последствия

### Положительные

- Отказ конфига на экранах раздела конфигурации виден с причиной и повтором, а не пустым местом.
- Экран наборов не показывает форму «наборов нет», пока конфиг не пришёл.
- Быстрый переход между экранами не показывает скелетон вовсе: данные уже в кэше.
- Скорость и счётчики до первого кадра потока не печатаются нулём.

### Отрицательные

- Переход на экран с медленным источником держит старый экран до 300 мс, прежде чем появится скелетон.
- Отказ чтения сообщается дважды: тостом и блоком. Тост нужен там, где блока нет — бар применения, фоновые перечитывания, — и `meta` у запроса одна на всех потребителей.
- `PendingPage` общий и не повторяет раскладку конкретного экрана.
- Скелетон проявляется CSS-анимацией: при `prefers-reduced-motion` задержка остаётся, а растворение длится те же 300 мс.

### Нейтральные или отложенные

- Пустые подписи в карточках обзора и вкладки конфигурации — записи в `docs/TechDebt.md`.

## Совместимость, миграция и откат

Контрактов демона решение не меняет. Ключи `toast.config.draft.fetchFailed`, `toast.config.versions.fetchFailed`, `toast.proxy.list.fetchFailed`, `toast.proxy.providers.fetchFailed` и `toast.route.explain.failed` переименованы в `source.*`: тексты тостов при этом не изменились.

Откат по частям:

- убрать `query` из загрузчиков и `default*` из роутера — экраны продолжат показывать скелетон блока;
- вернуть строки загрузки — примитивы `shared/ui` при этом останутся неиспользованными.

## Проверка решения

- `pnpm --filter web exec vitest run Editor Overview Connections DaemonTraffic`: отказ конфига показывает причину и повтор, повтор перечитывает; конфиг без правил называет это; графики до второй точки показывают загрузку, а не линию.
- `pnpm lint`, `tsc -b` — устаревшие методы Query в коде не встречаются.
- Браузер: на стенде с моками переход между экранами без мигания скелетоном; при остановленном моке конфига — блок отказа с причиной.
