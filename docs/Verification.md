# Requirement checks

Which check confirms which requirement: acceptance criteria (`AC-N`) and non-functional requirements (`NFR-N`) of [`openspec/specs/`](../openspec/specs/), which hold every built requirement, of the proposals in `openspec/changes/`, and interface principles (`UX-N`, [PRD](./PRD.md) section 7). A requirement in `openspec/specs/` counts as built. The links go from a requirement to its check; code does not name requirements or decisions. The decision behind this: [ADR-0076](./adr/ADR-0076-link-requirements-to-their-checks-not-code-to-documents.md).

`.github/scripts/trace-check.py` reads this table on pre-push and in CI (`make trace-check`). It fails when:

- a row names an ID that neither the PRD nor `openspec/` defines;
- the file of a row does not exist, or the named test, job or target is not in it;
- tracked code outside Markdown names a document: `ADR-NNNN`, a requirement ID, or the PRD itself;
- a requirement of `openspec/specs/` has no row (`--strict-coverage`);
- a row of [Checked by hand on purpose](#checked-by-hand-on-purpose) has no scenario or no reason;
- a relative link in `openspec/specs/` or `openspec/changes/` points at a file that does not exist.

It reports, without failing, the requirements checked only by hand, those checked by hand on purpose, and the `manual` rows outside that section: each of them is a check still owed.

## How to add a row

A requirement of an OpenSpec change gets its rows in the change's tasks, before the change is archived into `openspec/specs/`. A requirement can have several rows; a requirement of an open change can have rows for the part that is covered.

| Kind      | File                         | Check                                 | Runs                                          |
| --------- | ---------------------------- | ------------------------------------- | --------------------------------------------- |
| `go-test` | Go test file                 | function name, `TestX`                | `make test`, CI                               |
| `bench`   | Go test file                 | benchmark name, `BenchmarkX`          | by hand, `go test -bench`; fails no threshold |
| `vitest`  | test file                    | the test title or a part of it        | `pnpm --filter web test`, CI                  |
| `e2e`     | `apps/web/e2e/*.e2e.test.ts` | the scenario title or a part of it    | `pnpm --filter web test:e2e`, CI              |
| `script`  | shell script                 | a line the script prints at that step | where the script runs                         |
| `ci`      | workflow file                | job ID                                | CI                                            |
| `make`    | `Makefile`                   | target                                | by hand or from CI                            |
| `manual`  | empty                        | the scenario in words                 | by hand                                       |

File and Check are written in backticks, except a manual scenario.

A `manual` row in the table below is a check still owed. A part that cannot be automated, because it needs the router, its hardware or an event the bench cannot produce, goes to [Checked by hand on purpose](#checked-by-hand-on-purpose) with the reason. The decision: [ADR-0087](./adr/ADR-0087-keep-deliberate-hand-checks-apart-from-hand-checks-still-owed.md).

So far only emulated: an Apple M4 Pro at CPU 4× gave up to 105 ms, numbers in `apps/web/docs/guides/Performance.md` | the threshold is about the weak clients of the panel; the CI runner and a developer laptop are fast machines, and CPU throttling only approximates a slow one                                       |
